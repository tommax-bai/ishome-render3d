## 我的判断（不是裁决）

- **默认该换成 `frame-sill` 或 `frame-handle`，证据够换掉 `diagonal-cross`**：斜线在室内 6/12、揭顶 4/21 变成实体斜楔或残影，
  双框 + 门扇线两批 33 张门里 0 张残影；窗上十字在书房 2/3 读成柜子，双框 + 窗台线 3/3 读成窗。这两点上一批已经成立，本批揭顶
  又印证了门的那一半。
- **`frame-handle` 对 `frame-sill`：证据薄**。两者只差把手短横，本批能量到把手的只有客厅 #2 一扇门（3 张，把手 3/3 长出来）和揭顶
  三扇门（放大才看得见）；书房、主卧六张是同一张图。把手的代价是 seed2 门旁多了两块开关面板（`glazing-hatch` 也出过）。
  要说"把手让门更像门"，样本是 1 扇门 3 张；要说"把手不伤图"，样本是 3 张 + 揭顶 3 张。**换默认选哪个要用户拍**；我的倾向是
  `frame-handle`（超集、没有变差的例子、把手是室内唯一稳定"符号→构件"的门符号），但按数据只能说它不比 `frame-sill` 差。
- **窗的结论仍压在书房一扇窗上**（3 张，本批没增加）；揭顶的 24 张窗三方案全对，说明揭顶不区分窗的符号，补不了室内的样本。
  要补窗的样本得换 seed 或换机位（次卧、主卧两台都对着窗），不是重跑同一稿。
- **阳台宽窗从上面看，双框读不出玻璃**：3.15 m 的窗在揭顶图里只剩一条黑框，十字的竖梃反而让它读成窗。这是宽窗 + 揭顶的特例，
  要不要给宽窗加分扇线（`leaf-swing` 的中竖梃那种）是新画法，没数据，不在本批。
- **入户门室内机位在今天的取景规则下站不出来**：玄关进深 1.23 m，平视下地板进不了画面。要看入户门的室内图，要么规则允许低头
  （`ROOM_PITCH_DEG` 固定 0，改它是裁决），要么允许"目标房间地板占比 0 但目标洞口在画面里"这类按洞口取景的规则——两条都是新规则。
