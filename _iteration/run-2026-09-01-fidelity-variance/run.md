# 真跑记录：同一份输入，写实化出来的户型每次都不一样（2026-09-01 晚）

> **写完不改**——它是判据的证据（《纪律·日志正文不改》）。
> 这份记录**推翻了同日早些时候的一个结论**，见末节。

## 本来要验什么

上一轮（`run-2026-09-01-realism`）照出"条件图信息越少，模型改得越多"：真户型的底渲是光壳
（上游不给家具），写实化时内隔墙漂得比带家具方块的 fixture 明显。据此做了家具摆场 mock，
本轮验它是否能把几何按住。

## 对照设计

同一套真户型几何、同一台揭顶相机（`pitch −52° / yaw 35° / fov 45°`）、同一份代码，
**只差有没有 mock 家具**。条件图都是 `geometry + line` 两路。

两组的线稿底渲**外接框逐像素相同**——`x[265,1005] y[189,884]`；
边像素 23022（光壳）对 23331（有家具），**多 309 个，1.3%**。
也就是说：输入几何完全一样，输出的任何差别都是模型给的。

## 三跑三个样

| 跑 | 条件图 | 结果 |
|---|---|---|
| 光壳 | geometry + line | 线稿描红**盖满整个模型，轮廓分毫不差** |
| 有家具 · 一 | 同上 +1.3% 边像素 | 右侧**凭空多出一整间主卧**（线稿外接框到不了那儿） |
| 有家具 · 二 | 与上一跑**逐字节相同的输入** | 把几个房间**合并成大开间**，红线大片对不上 |

**条件图差 1.3%，输出的几何差异远大于此。所以这不是家具的事**——
是这条通路**同一份输入的输出方差本身就极大**。原假设（家具能把几何按住）**不成立，
但也没被证伪**：家具的效果被方差淹没了，这一轮的样本量测不出来。

## 这件事的后果

**单张生成不能直接发给业主。** 它可能给人家凭空加一间房，也可能把三室拆成大开间。
这不是"图好不好看"，是会把错的户型发到业主手上。

**正路是保真度门禁**：生成完拿线稿量一次，不过线就重出。本项目有现成先例——
render2d 的外轮廓闭合率低于 0.90 整张不出。**阈值要有数据才能定**（《纪律·阈值有数据才定》），
而定阈值之前先得有噪声底：同一输入连跑 N 次，分数的散布就是噪声底，
**任何两组之间小于噪声底的差距都只能写"测不出差别"，不许排名次**。

## 推翻的那条

同日早些时候记下的口径"**把底渲的构图摆成目标构图，几何就锁住了**"
（见 `run-2026-09-01-realism` §一）**是单样本得出的，本轮之后必须降级成待验证**。
那几张锁得好的图里有多少是运气，现在说不准。**不能当口径用。**

方法论上的教训写在这儿：**这个通路上，任何"A 比 B 好"的结论都要先过噪声底**，
单样本对单样本一律不作数。
