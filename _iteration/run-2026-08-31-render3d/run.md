## 真数据照出来的三件（合成几何一件都照不出来）

1. **零长墙段 5 段**：真跑存档 61 段墙里第 32/36/47/49/55 段 `start_ratio == end_ratio`。
   2D 那侧画一条零长线等于没画，从没被绊住；三维起体是零体积退化块。**跳过 + 计数**
   （`ScenePackage.degenerate_wall_count`），不静默。
2. **洞落在墙段之间的空隙里，不与任何墙段相交**：15 个洞起初只挖出来 5 个。缝恰好是
   **一个源像素**（竖向 0.000682 / 横向 0.000926 归一化，1080px 宽的图上 1px ≈ 1.4 cm）。
   所以三维不是"挖洞"是"往空隙里补"——补过梁（洞顶→层高）与窗下墙（0→窗台），
   厚度与中心位置抄同直线最近那段墙，**一个厚度都不编**。补完 15/15。
   不补的话门窗洞是从地面通到天花的大开口。
3. **尺子锚点**：先按 `plan_box` 外接框定，量到吻合率 0.708、图上家具明显偏挤。
   改为**外轮廓围合面积**——"外墙中心线围合的面积"就是套内建筑面积的几何定义，
   两边说的是同一个量，**不引入任何系数**。实测外接框比外轮廓大 **4.12%**，尺子偏小 2.00%。

## 这一轮定下来的口径（都写在代码 docstring 里）

- **bird 机位剔 ceiling**，不加剖切面：剖切要多一个"切在哪个高度"的参数，今天没有依据能定；
  剔的是这一个机位的渲染，不是场景包。剔完可见网格 106 → 164。
- **深度**：16 位、**近亮远暗**（深度 ControlNet 一系的通行口径），`near_m`/`far_m` 取本帧
  实际命中的两端、随包带出，没有这两个数还原不回米。
- **线稿**：不做图像滤波猜边缘。两条判据都是几何事实——`id_buffer` 相邻不等；按法向把
  当前像素所在平面外推到邻居视线上，残差 > 2% 算断开（连续面上残差恒为 0，2% 只是浮点余量）。
- **遮罩**：16 位索引图，0 是背景，索引 ≡ 网格在场景包里的下标 + 1（剔除只让索引缺席，
  剩下的不挪位）。
- **不做背面剔除**：上游绕序不保证一致，剔错了室内直接看穿墙。
- 四路统一"**没有东西 ＝ 0**"，四路一致性因此可自查。

## 没解的，留在这儿

- **`area_match_ratio` = 0.737 的成因没查完**：换锚点只贡献 2%，其余是房间遮罩本身没覆盖到的
  地方（阳台与走廊没成房间、内墙占地、真跑 2.7% 未认领像素）。bird 图上那几片黑区是同一件事。
  **没设阈值**（《纪律·阈值有数据才定》），今天只把这个数算出来带走。
- **`CameraSpec` 说不出"站在房间哪儿"**：只有 `room` + `eye_height_m`，眼点被钉在地板质心。
  室内实拍该站短边靠墙处。主卧（2.0m 深的床放进 3.46m 的房间必然横跨质心）与小孩房
  （近正方，长轴两头真渲都不过关）两台机位因此**撤掉了，没有在数据里凑假位置**。
  增字段的时点写死＝真上游能给出机位那一批（相机本来就是取景那一步的输出）。
- **洞两侧各留一道 1.4cm 通高的缝**（真数据自带的墙段间隙）：消掉它要引一个"拉多远算合理"
  的阈值，一份样本定不了。1024px 底渲上约 1 个像素。
- **两个 activity 仍是存根**。接通要三件：①只依赖 oss2 的落桶模块（形态照抄 reportrender
  的 `book_store`：只写不签）；②`design_package_key` / `scene_package_key` / 底渲四路的键
  进 contracts `registries/object_keys.md`，产物类型进 `registries/artifacts.md`——今天两张表
  里都没有三维的位置；③函数体换成"取键 → 调纯库 → 写桶 → 返回键"。
