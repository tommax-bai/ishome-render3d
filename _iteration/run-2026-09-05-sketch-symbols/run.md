## 做了什么

1. **符号方案开关**：纯库参数 `render_base_views(..., sketch_symbols=...)` + CLI `--sketch-symbols <name>`，默认值 ＝ 现在的 `diagonal-cross`，不给就是它；不认的名字炸（库 `BaseRenderError`，CLI argparse 退出码 2）。方案只换洞口内的符号，画的边、编码（0/255 黑底白线）、尺寸、深度遮挡全同；**四路（几何/深度/线稿/遮罩）一个字节不动**（`tests/test_frozen_views.py` 照旧全过；三台机位默认方案的 `sketch.png` 与 `run-2026-09-05-opening-kind-consume/` 那批逐字节相同，`渲控制稿与拼图.py` 断言过）。
2. **四个方案**（画法写死在 `base_render.SKETCH_SYMBOL_SCHEMES` 的 docstring，尺寸常量各有出处；"外框"＝洞口边界在墙厚中心平面上的矩形，门三边不画门槛线、窗四边；"内框"＝外框内缩 0.08 m）：
   - `diagonal-cross`（默认，上一批那套）：门＝洞内左下到右上一条斜线；窗＝洞内十字。
   - `frame-sill`：窗＝外框 + 内框 + 窗台线（洞下沿再向下 0.06 m、两端各伸出 0.04 m，画在**朝相机那一面的墙面**上——画在墙厚中心会被窗下墙自己挡掉），不画十字；门＝外框 + 门扇线（离沿墙坐标小的那侧洞边 0.12 m 的一条通高竖线），不画斜线。
   - `glazing-hatch`：窗＝外框 + 内框 + 三条 45° 斜向短划（起点在内框宽 18%/34%/50%、高 55% 处，长 0.30 × 内框短边），不画十字、不画窗台线；门＝外框 + 把手（离沿墙坐标大的那侧洞边 0.06 m、长 0.12 m、离地 1.0 m 的一条短横）。
   - `leaf-swing`（本批多加的第三个，**没真跑**）：门＝外框 + 一扇朝相机这一侧开到 45° 的门扇（铰链在沿墙坐标小的那侧；画顶边、底边、自由竖边三条三维线段）；窗＝外框 + 内框 + 窗台线 + 中竖梃（双扇分扇线），不画横梃。相机在墙哪一侧由机位 eye 定，所以它是四个里唯一随机位变几何的。
3. 测试 18 条新增（`tests/test_sketch_symbols.py`）：默认不变且显式给默认逐字节同；不认的名字炸；换方案四路逐字节不变、控制稿变；每方案确定性、同编码；每方案同一个框按门/窗画线段集合不同、入户门同门、过口为空；三个新方案各自逐点验（该白的白、该黑的黑，含窗台线在朝相机那一面、门扇朝相机开）；相机在墙另一侧时窗台线换面、门扇换向；从输入包编出来的洞每方案门窗都画得出、CLI 出的字节与纯库同方案一致、默认与不给一致、argparse 拒不认的名字。全套：ruff / mypy strict / import-linter 2 契约 / pytest **224 全过**（基线 206 + 18）。
4. **控制稿**：`渲控制稿与拼图.py` 用 16 洞机位包（`run-2026-09-05-opening-kind-consume/design-package-真值138-16洞-roomcams.json`，1280×960）渲书房 / 主卧 / 客厅三台 × 四方案，存 `<方案>/<机位>/sketch.png`；拼图 `montage-方案并排.png`（行＝机位，列＝四方案）。
5. **真跑**：`frame-sill`、`glazing-hatch` × 三台机位 × seed 1/2/3 ＝ **18 张，全部成功**，`<方案>/<机位>/seed{N}.png` + `.prompt.txt`（提示词，与上一批逐字同）+ `.png.log`（CLI 全部输出，分数与耗时在里面）。imagegen 留档的 `seed{N}.sketch.png`（送出去的控制稿，同一张转 RGB）删了不入库。拼图 `montage-<方案>.png` 三张（含 `diagonal-cross`，图取上一批、控制稿取本目录默认方案），版式同：行＝机位，列＝控制稿、seed1/2/3、seed1/2/3 叠控制稿红。

## 判读：每个洞口渲成了什么

三台机位画面里能看到的洞口（编号＝16 洞洞口表，`run-2026-09-05-opening-kind-consume/run.md`）：书房＝远墙 **#6 窗**；主卧＝左边斜视的 **#2 门**（主卧/客厅，离相机 3.8 m，几乎侧看）+ 右边 **#1 门**（卫生间/主卧，4.5 m）；客厅＝左边 **#8 门**（厨房/卫生间那扇，洞里透过去看得见厨房 **#5 窗**）+ 右边 **#2 门**（主卧那扇，5.2 m）。每张 2 窗 4 门，三 seed 共 6 窗 12 门。

## 我的判断（不是裁决）

- **门窗读对率最高的是 `frame-sill`**：窗 6/6（书房那扇 3/3，对照 diagonal-cross 1/3、glazing-hatch 1/3），门 11/12，门里没有一张出现斜线残影；门扇线在客厅 #2 三张里都被画成了真门扇。`glazing-hatch` 的短划在书房被当成黑色亮面板上的反光（2/3 黑板），比十字没好；但它的把手点在客厅 #2 三张里都长出了真把手，是本批唯一稳定"符号→构件"的门符号。
- **要不要换默认**：数据支持把默认换成 `frame-sill`，但换默认要用户拍（本批没动默认）。样本小：窗的结论实际压在书房一扇窗的 3 张上；没跑揭顶机位（外墙窗从外面看、窗台线画在朝相机那一面，形态还没验过）；没跑过口与入户门。
- 下一步可试的（没做，写清）：`frame-sill` 的窗 + `glazing-hatch` 的把手合成一个方案；`leaf-swing` 只画了没跑，近门下门扇成大板，要跑先解决它。
