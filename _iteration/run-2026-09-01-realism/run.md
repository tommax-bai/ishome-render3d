# 真跑记录：底渲喂进生成式写实化（2026-09-01）

> **写完不改**——它是判据的证据（《纪律·日志正文不改》）。
> 本轮**没有改本仓一行代码**：相机是数据，改的是设计包 JSON。

## 跑了什么

三维底渲（`base-render` 的四路产物）作为条件图，喂给 imagegen 的生成式写实化通路，
看能不能出照片级效果图。起因＝用户看了底渲说"比较粗糙，缺乏科技感"。

- 逻辑模型名 `realism-pass.default`（infra 网关配置里已备好，物理模型 doubao-seedream-5-0-pro-260628）
- 走 **imagegen 的纯库 `image_gateway`**，不经 Temporal、不落私有桶——`apply_realism_pass`
  仍是存根。**本轮没改 imagegen 一个字节**（那个仓另有 session 在改，工作树钉在 518f032 上跑）。
- 共 **7 次真调用**，每次 97~131 秒。提示词随图存档。

## 三件真数据照出来的事

### 一、模型会自己转相机，除非底渲已经是目标构图

首跑把正俯视底渲（`pitch −90°`）直接喂进去，**模型把相机转成了 3/4 轴测**——提示词里
"保持机位、视角、焦距不变"那句没拦住。它想要揭顶模型的构图。

改法是**给它那个构图**：把 bird 机位改成 `pitch −52° / yaw 35° / fov 45°`，底渲出来
就已经是揭顶模型。改的是一份设计包 JSON，**本仓一行代码没动**。此后几何明显锁住：
外轮廓与主要内墙的线稿描红能压在渲出来的墙上。

同一套几何换偏航 215° 再跑一次，认得出是同一户——不是一次侥幸。

### 二、这个型号一次吃得下多张条件图

探针：`image` 传数组送两张进去，调用成功，回执 **`usage.input_images = 2`**。

所以底渲四路不是只有几何那一路有用，线稿（几何事实边）能当第二路结构条件一起送。
连带一条：imagegen 纯库里 `input_images != 1` 那道守卫（防"图生图静默退化成文生图"），
**语义上该是"等于送进去的张数"**，写死 1 会把合法的多图调用判成失败。已告知那条线的 session。

`usage.input_images` 是这个型号的方言字段，换型号守卫要重新设计。

### 三、条件图信息越少，模型改得越多

用户的真户型图跑通了：82 段墙、59 段真外轮廓、19 个洞、7 间房 → 底渲 → 效果图。
房间在图上一一认得出。**但内部隔墙漂得比 fixture 那次明显。**

差别看得见：fixture 的底渲有家具方块、有地板材质色；**真户型的底渲是光壳**——上游的
几何产物不提供家具、不提供材质，于是可参照的信息少一大截，模型的自由度就大。

这是"条件图强度 → 下游几何保真度"的第一个真样本。

## 顺带结掉的一笔账：那个 0.737

此前在 fixture 上量到"地板面积只有输入套内面积的 73.7%"，缺口 22.9% 全堆在图幅边缘，
当时没结论。真数据一跑：

| | fixture | 真户型 |
|---|---|---|
| 外轮廓段数 | 4（拟真补的矩形） | **59（真的）** |
| 地板面积 ÷ 输入套内 | 0.737 | **0.951** |

**旧的缺口不是数据错，是 fixture 的外轮廓本身是补的矩形，把分母撑大了。**
真数据剩下的 4.9% 就是内墙占地，合理。这条此前挂着的"没解的四件"之一可以划掉。

## 尺子：真户型这次是量出来的，不是编的

几何产物里一个绝对尺寸都没有，只有比例。用户还没给建筑面积——**不编一个**
（《纪律·拿不到就说没有，不许填猜的值》），改从图里量：

19 个洞口里最窄的那批内墙洞有 4 个挤在同一档（图幅归一化 **0.0602**），那是门。
按常规内门洞口宽 0.80 m 当锚：

- 图幅 1 单位 = **13.29 米** → 套内 **91.0 ㎡** → 建筑面积约 **114 ㎡**（得房率按 80% mock）
- 分间：客厅 23.0　次卧 21.1　主卧 14.8　卫生间 12.1　书房 7.2　厨房 6.6　阳台 6.2
- **敏感度**：内门若是 0.75 m → 100 ㎡；若是 0.90 m → 144 ㎡。**这个锚值得用户确认。**
- **交叉验证**：以 114 ㎡ 入包后，外轮廓法反推出 12.97 m/单位，门宽法是 13.29——
  两条独立路子差 **2.4%**。

高度整段仍是 mock（`heights_source=mock-default`），洞口种类仍按"外墙洞当窗、
内墙洞当门"的档位判——**入户门因此被画成了带 0.9 米窗台的窗**。

## 没解的

1. **窗洞被模型放大**：提示词里"保持洞口尺寸"那句没拦住，渲出来是落地大窗。
2. **家具整段没有**：上游只给墙、洞、房间，效果图里满屋陈设全由模型自由发挥。
3. **洞口种类是猜的**：上游几何里没有"门还是窗"这个字段。正路是列进对上游的要求清单，
   **不在本仓发明猜测规则**。
4. **室内平视机位没法看**：`resolve_camera_pose` 让 room 机位站在房间面积质心上平视，
   等于站在屋子正中对着墙。这是取景算法的事，不是写实化的事。
